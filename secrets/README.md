Сервис `secrets` на Go: текстовые секреты с TTL, запросы доступа, решения автора,
история открытий и события для уведомлений. Все файлы сервиса находятся в `secrets/`.
Внешний API gateway проверяет подпись RS256 и срок действия JWT. Только после успешной проверки он удаляет
полученные от клиента `X-User-ID`, `X-User-Email`, `X-Real-IP` и устанавливает их
заново: `X-User-ID` из claim `user_id`, `X-User-Email` из claim `email`,
`X-Real-IP` из адреса клиента на gateway. При неверном JWT или обязательных claims
gateway отвечает 401, не передавая запрос в сервис. Передавать клиентские значения этих
заголовков как доверенные запрещено. `secrets` JWT не проверяет; `Authorization` игнорируется.

Контракт gateway → secrets действует для всех восьми операций:

| Заголовок | Обязателен | Значение |
| --- | --- | --- |
| `X-User-ID` | Да | Ровно один ненулевой UUID в каноническом виде `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`, нижний регистр |
| `X-User-Email` | Да | Ровно один email без отображаемого имени, до 320 байт |
| `X-Real-IP` | Нет | Ровно один IPv4/IPv6-адрес без порта, списка адресов и зоны интерфейса |

Отсутствующий, пустой, неверный или дублированный `X-User-ID` / `X-User-Email`
возвращает 401 с `Content-Type: application/json; charset=utf-8`:

```json
{"error":"gateway_identity_required","message":"Отсутствуют или некорректны данные пользователя"}
```

Без корректного единственного `X-Real-IP` для истории чтения используется IP
прямого соединения. В рабочем развёртывании сетевой доступ к сервису имеет только
доверенный gateway; привязка Compose к loopback предназначена для локальной отладки.

Нужны Docker с Compose v2, Make и OpenSSL; для разработки — Go 1.26+.

```sh
cd secrets
make init
make up
```

Compose поднимает только `secrets`, PostgreSQL, Redis и RabbitMQ.
API доступен локально на `127.0.0.1:8000`; порты инфраструктуры не публикуются.
В `.env` можно изменить `PORT` и `PUBLIC_BASE_URL`. Swagger UI:
[http://localhost:8000/docs](http://localhost:8000/docs),
спецификация: [api/openapi.yaml](api/openapi.yaml).
Статические файлы Swagger UI загружаются с CDN; API работает независимо от него.

`make init` создаёт `.secrets/master_key` (32 случайных байта), `postgres_password`
и `rabbitmq_password`, сохраняя существующие файлы. Они исключены из Git и сборки
образа и подключаются через Docker secrets. Замена мастер-ключа делает сохранённые
секреты нечитаемыми. Каталог `.secrets/` имеет права 0700, файлы доступны для чтения
непривилегированному процессу контейнера. Миграции применяются при запуске.

Пример HTTP-запроса от gateway после проверки JWT:

```http
GET /secrets/c2a9e5d4-1f0b-4b8e-8d3a-6e7f9a1b2c3d HTTP/1.1
Host: secrets:8000
X-User-ID: 7f3e2a10-4c1b-4d7e-9a55-0b8e1f6c2d91
X-User-Email: owner@example.test
X-Real-IP: 2001:db8::42
```

| Метод и путь | Действие |
| --- | --- |
| `POST /secrets` | Создать секрет и получить ссылку |
| `GET /secrets` | Свои активные секреты |
| `GET /secrets/shared` | Секреты с одобренным доступом |
| `GET /secrets/{id}` | Прочитать или автоматически запросить доступ |
| `GET /secrets/{id}/requests` | Запросы и просмотры для автора |
| `POST /secrets/{id}/requests/{request_id}` | Решение `approve` или `deny` |
| `DELETE /secrets/{id}/access/{user_id}` | Закрыть одобренный доступ |
| `DELETE /secrets/{id}` | Отозвать секрет |

Текст ограничен 10 КБ; TTL — от 300 до 604800 секунд, по умолчанию 86400.
Чтение возвращает 200 с текстом, 202 для pending, 403 после отказа или закрытия,
404 для отсутствующего или истёкшего секрета. Ошибки имеют поля `error` и `message`.
Название хранится открыто и попадает в события; не включайте в него секретные данные.

Текст шифруется AES-256-GCM со случайным nonce и UUID как AAD. PostgreSQL — источник
истины; Redis хранит только шифротекст и nonce до пяти минут, без записи на диск.
Права проверяются при каждом чтении. Истёкшие секреты недоступны сразу и удаляются
фоновой задачей раз в пять минут; запросы и история удаляются каскадно.
События сохраняются атомарно через PostgreSQL outbox и доставляются с подтверждением
в exchange `app.events`, очередь `notification.events`. Текст в события не попадает.
Потребитель дедуплицирует события по `event_id`. Отправка email реализуется отдельно.

`make build` собирает бинарник, `make run` запускает его с окружением вызывающего,
`make check` проверяет форматирование, `go vet` и тесты с `-race`.
`make integration` собирает и запускает Compose, затем прогоняет тесты всех 8 ручек,
PostgreSQL, Redis и RabbitMQ в отдельном Go-контейнере, без публикации портов инфраструктуры.
`make logs` показывает логи; `make down` останавливает стек, сохраняя данные.
На SIGINT/SIGTERM сервис ожидает HTTP-запросы до 15 секунд, затем завершает фоновые
задачи за 5 секунд и закрывает подключения. Compose даёт контейнеру 25 секунд.
